# QuickExit v0.5 development and validation

Validated 9 October 2026. No commits, pushes, deployments, or hosted Supabase mutations performed.

## Starting point

The working tree was clean. Stable v0.4 checkpoint: `907808c` (QuickExit v0.4 — Perfect the Trade), followed by v0.4.1 security checkpoints `d9f7b67` and `f5c905a`. Development started from `e6ecdc3`, which already contained market intelligence, including a candlestick implementation. This phase adds no candlestick functionality.

Inspected workspace navigation, execution engine, portfolio accounting, local persistence, account synchronization, Coinbase market service, database migration, existing tests, styles, and the installed Next.js client-component guide before editing.

## Changes

- Markets is the initial workspace view, with searchable BTC, ETH and SOL names, symbols and existing visual marks. Solana now uses its recognizable three-bar mark. Selecting an asset uses the existing Trade workspace and durable asset preference, and selects live pricing for a new trade.
- Market rows independently poll validated Coinbase Exchange EUR quote/statistics endpoints. They display observed timestamps and loading, live, delayed, stale or unavailable status. Missing prices and unavailable 24-hour changes use explicit placeholders. Cached quotes remain marked stale on errors. No demo reference prices enter the Markets list.
- Preserve the existing single-active-position model: selecting another market while a position is open remembers the next asset and returns to the existing position, with an explanatory message.
- Home and Trade display cash, allocated capital, estimated net liquidation portfolio value, separate realized/unrealized net P&L, and simulated transfers out. Freshness updates periodically. Portfolio math continues to use the centralized execution engine and existing accounting; amounts already include entry fees, and paid fees are never subtracted a second time.
- Performance statistics exclude example history and include completed trades, wins/losses/breakeven, win rate, average realized net P&L, cumulative realized P&L and paid trading fees. Paid fees include active entry fees but exclude hypothetical future exit fees. Legacy trades have no invented fees.
- Responsive SVG performance chart shows cumulative realized net P&L at recorded receipt exit dates. All/1D/1W/1M ranges, single observations, empty ranges, and an expandable recorded-data list are supported. Current unrealized P&L is explicitly separate. Transfers do not change trading performance.
- Trading journal is available under a completed real paper trade's receipt in Positions. Notes have a 2,000-character limit, explicit save, deletion via an empty note, persistence across refreshes, and account-scoped synchronization. Notes are separate from frozen execution receipts and cannot change settlement accounting. Examples cannot receive notes.
- Live manual exits now require a fresh quote. Stale data keeps the position open with an explanatory announcement.
- Mobile navigation exposes Markets, portfolio Home, Trade, Positions and Cash Out; Settings remains accessible through the top-bar shortcut. Activity remains accessible from Trade's recent activity. Existing trading, transfer, reset, and account flows are retained.

## Compatibility

No database changes or migration changes. The SQL payload check already accepts the unchanged version-3 aggregate and BTC/ETH/SOL selection. Optional journal fields are validated and explicitly serialized within that aggregate, using existing device/account save and recovery paths. Existing version-1/2/3 snapshots and legacy accounting continue to restore. Existing immutable receipts remain intact.

No project dependencies added. Browser verification used a temporary external Playwright install after the supplied browser runtime failed during setup.

## Remaining limits

- XRP, ADA and DOGE are unsupported. Provider/execution coverage and the saved-workspace asset constraint currently cover BTC, ETH and SOL. Expanding that set requires a separately reviewed compatibility change.
- Historical total portfolio values and unrealized valuation history were not recorded by the existing application. The chart therefore shows dated realized performance, not an invented total-equity history. Undated legacy P&L contributes to totals and the carried-forward realized balance but gets no fabricated date.
- Hosted accounts remain gated off by the existing production configuration. Account synchronization and database security passed local automated tests; live hosted account verification was not performed and hosted data was not modified.
- Quotes are indicative exchange last-trade prices and remain subject to outages/delay; the existing two-minute execution freshness limit remains in force.
