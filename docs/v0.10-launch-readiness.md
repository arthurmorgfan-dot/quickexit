## Local reliability changes

- Live-price buys and sells require a connected or refreshing feed and a valid fresh quote. A recent cached quote alone cannot authorize a trade when the feed is unavailable or idle after refresh. Offline events immediately mark the feed unavailable; late quote responses cannot reconnect it while offline.
- Existing pure execution calculations, historical migration formats, receipt validation, journal storage, and database migrations remain unchanged. UI buttons reflect the same trading readiness rules.
- Bounded in-process token buckets reject excess market, account, and password requests with generic 429 responses and Retry-After. Account owner limits use server-verified identities. Global budgets limit work before handler authentication and cannot be bypassed by changing market query strings or forwarded IP headers.
- Safe build metadata now identifies v0.10. No secrets or new dependencies were added.

These limits reset on process restart and are **not distributed abuse protection**. They do not protect direct Supabase authentication/RPC requests or authentication performed earlier by middleware. Edge/shared request limits, hosted auth quotas, request deadlines and body limits must be verified before public accounts. Rate-limited cloud saves preserve the existing pending operation and retry semantics.
