# QuickExit v0.11.6 — Premium Trading History

Local implementation ready for review; not committed or deployed.

## Result

History opens on actual completed trades, with an all-actual-trades performance overview that reuses existing `performanceStatistics`: realized net P&L, count and win rate. Examples never contribute to those totals, and zero trades show an unavailable win rate rather than a fabricated percentage. The overview clearly identifies device Demo versus account paper history and remains independent of row filters.

Records, asset, result and inclusive local-date filters support the existing BTC/ETH/SOL records. Undated legacy trades and examples do not satisfy date filters; no dates or costs are reconstructed. Reversed date bounds display a clear message. Filters never mutate trades. Examples remain available through the explicit Records control and retain illustrative labels.

Mobile cards emphasize asset, recorded date, realized net P&L, investment and exit reason. Desktop uses compact rows with inline receipt actions; tablet preserves legible rows and wraps filters. Receipts reuse the existing immutable execution renderer. Examples have no editable journal; actual trade notes remain separate from execution records. Receipt opening focuses its heading and closing restores focus to the matching visible opener inside the positions component after rendering, rather than relying on a global timed selector.

Activity shows the newest five entries and exposes all earlier entries through a native disclosure. Numbering remains accurate across both sections. Account History uses account activity labels, and Demo keeps its existing Demo labels. This reduces vertical space while retaining every activity record. Journal and receipt spacing use the existing dark surfaces and mint accents.

Authentication, account isolation, portfolio initialization confirmation, cloud transport, execution math and receipt calculations were not changed. Unresolved and uninitialized account views remain gated by the existing workspace guard.

## Build-isolation incident and controlled-test boundary

The first production-build command accidentally ran in the main project, replacing generated `.next` files before failing on the existing named page export. This was a build-path mistake; it must not be described as untouched generated artifacts. The v0.11.5 generated files were rebuilt from a reconstructed isolated copy and restored. That recovery copy used a temporary type-check bypass for the pre-existing route export; v0.11.6 fixed the export and passed full production TypeScript validation. No persistent configuration or environment file was changed.

The original port 3000 process was never stopped; its PID remained 17159 and the non-authenticated `/api/build` check still returned v0.11.5 and the original identifier. The retained controlled-preservation browser/context was not navigated, refreshed, closed, inspected or written, and its recorded baseline file was not changed. No account sign-in, logout, SQL, hosted operation, commit, push or deployment occurred. Future continuation of the preservation test should revalidate the restored v0.11.5 server under its separate preparation approval; no browser/session readiness test is claimed after artifact recovery.

## Limits

Visual/browser checks used Chromium and local Demo fixtures, not Safari or hosted account sessions. The decoder always restores canonical examples, so the browser “empty” case means zero actual trades with examples hidden; a truly empty record list is covered by component tests. Date filtering deliberately excludes undated records. Win rate is descriptive, not predictive, and includes breakeven trades in its denominator. The all-actual overview does not recalculate for the filtered rows; its caption makes that scope explicit. No large-history pagination or new statistics/provider functionality was added. The controlled Demo-preservation authentication comparison remains pending and is not completed by these isolated tests.
