# QuickExit v0.7 — first user experience and private beta

## Scope and data compatibility

The optional Markets introduction explains real Coinbase prices versus simulated
balances, executions, fees and transfers. Explore and Skip both remember dismissal
in `quickexit.introduction`; Settings keeps a readable guide. Blocked storage is
reported, with dismissal lasting for the current visit only. No portfolio key is
repurposed. Existing version-3 portfolios, receipts, journal notes and chart
preferences remain compatible. Reset is explicit, defaults keyboard focus to Keep,
and now names receipt and journal deletion in its warning.

Feedback is a downloaded text file containing only the tester's selected type and
written description. There is no backend submission, analytics, automatic identity,
portfolio attachment or stored feedback draft. The invitation must provide a real
monitored channel; testers manually send the file there. Do not imply delivery.

Offline messaging distinguishes an available device copy from live price freshness.
Existing engine checks still reject stale live buys/sells and stale automatic exits.
No execution arithmetic, Supabase schema, dependency or configuration changes.

## Authentication and synchronization audit

Accounts remain disabled by the existing explicit public feature flag. Configuration
validation rejects privileged keys and unsafe origins. Browser and server clients
fail closed when disabled; signup remains unavailable. The workspace no longer
advertises account creation while that gate is closed.

Server paper requests verify `auth.getUser()` on every request, derive ownership
from the verified identity, require same-origin JSON writes and bound request size.
Password changes independently verify the matching user. Authentication callbacks
use provider verification and constrained redirects; error text avoids token leaks.

The reviewed migration forces RLS on both tables. SELECT policies use `auth.uid()`;
anonymous access and direct authenticated writes are revoked. The atomic RPC uses
an empty search path, derives its owner from `auth.uid()`, locks that owner's row,
checks revisions and records operation UUIDs per owner. Retried commands cannot
commit twice; stale concurrent writes report conflict. Its security-definer owner
and effective deployed grants must still be checked on the actual hosted project.

Local PGlite tests execute the actual migration and verify A/B ownership isolation,
anonymous rejection, denied direct mutations, duplicate replay and revision behavior.
Store/transport tests verify import, separate guest/account caches, refresh and
second-device restoration, expired sessions, offline retries, lost responses,
queued commands, conflict recovery copies and stale-account callbacks. These prove
local behavior, not deployed Supabase configuration.

Cloud aggregates are client-authored simulated state. RPC shape validation and app
receipt validation do not constitute a server-authoritative financial ledger or
prevent a user forging their own plausible paper results. Never use this design
for real funds, competitive prizes or trusted performance rankings.

## Hosted blockers — no hosted writes performed

Follow [development acceptance](supabase/development-acceptance.md) and its read-only
final SQL verification before separately approved **development-only** account tests.
Need actual hosted evidence for migration/body/grants/function-owner parity, RLS
with A/B JWTs, confirmation and recovery email delivery, redirect allowlists,
session refresh/logout, two-device synchronization, idempotent lost-response replay,
conflicts and receipt stability. Current public registration must remain off.
Supabase's own signup setting must also be reviewed: the app feature flag alone
does not disable direct provider signup. Do not change it without approval.

## Validation record

Local validation on 2026-10-09: TypeScript, ESLint, production build and all 144
automated tests passed. Browser checks at 320, 390, 768 and 1440px verified intro
persistence without portfolio changes, keyboard dismissal, reset cancellation and
focus, feedback file contents, offline/reconnect messaging, blocked storage, chart
interactions/preferences and journal persistence. No horizontal overflow or runtime
errors were detected. Accounting engine, receipt storage and migration files are
unchanged. No hosted verification, commit, push, deployment or hosted data changes
were performed.
