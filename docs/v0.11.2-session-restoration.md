# QuickExit v0.11.2 — Reliable Session Restoration

Local implementation, awaiting a separately approved hosted session test.

## Behavior

Initial auth events do not decide whether a session exists. The explicit getSession lookup determines authenticated versus signed-out state; errors retain an unresolved account lock and show exactly: "Session restoration unavailable. Your account data has not been changed." Real subsequent auth transitions supersede the initial lookup, queued older transitions are ignored, and detached subscriptions cannot apply results. Explicit SIGNED_OUT continues to restore guest mode. Explicit demo=1 and disabled account gates still bypass account restoration.

The hook sets the auth lock before hydrating device state and exposes restoring, authenticated, signed_out or restoration_unavailable status. Unhydrated views show checking rather than a guest identity. Markets, header and account controls show neutral restoration text and hide balances until resolved. Creation/import, conflict resolution, reconciliation and background retries are guarded while authentication is uncertain. Portfolio confirmation safeguards, feature flags and public-registration restrictions remain intact.
