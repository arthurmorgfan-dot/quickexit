## Implemented

- Four chart types: Line, Candlesticks, Area and OHLC bars. Line is the default for new users, with a 15m candle interval. Style switches preserve selected asset and interval, reuse observations, and issue no extra history requests.
- BTC, ETH and SOL EUR markets continue to use the genuine Coinbase Exchange OHLCV provider. No synthetic prices, candles, forward-filled closes or substitute intervals.
- Interval controls distinguish candle duration from the former history-range controls. Older uppercase history API ranges remain accepted for compatibility; new UI controls use lowercase interval names.
- Crosshair price and UTC timestamp, with full OHLC readout for candles/bars. Explicit EUR price-axis and UTC time-axis labels, plus an accessible timestamped OHLCV table.
- Mouse drag, horizontal touch drag, pinch/wheel zoom, Zoom in/out buttons and Fit history. Vertical page scrolling remains available on mobile.
- Optional base-asset trading volume in a separate pane; optional SMA 20 and SMA 50 overlays, calculated from contiguous observed closes. A missing interval restarts SMA warm-up. Insufficient observations produce no overlay values.
- Missing observations retain genuine timestamps and generate only whitespace markers, never price bars. Missing interval counts, source, fetch time, latest observed bucket time, stale/delayed history and forming-bucket notices are visible.
- Device-local versioned chart preference storage (`quickexit.chart-preferences`) persists type, interval, volume and both SMA toggles independently of paper-trade receipts and balances. It synchronizes changes between tabs. Invalid/unavailable storage safely uses defaults or temporary choices with an explicit save-status message.
- Chart instance persists across style/indicator changes; series updates preserve the visible logical range. Initial fitting waits for non-zero visible dimensions, including charts loaded inside closed mobile disclosures.
- High-frequency crosshair updates change only the readout; they do not rerender the chart/data table through React. Chart rendering is memoized and SMA calculations are reused for unchanged observations.

## Supported intervals

| Interval | Provider granularity | Initial history window | BTC / ETH / SOL |
| --- | --- | --- | --- |
| 1m | 60 seconds | About 4 hours | Supported |
| 5m | 300 seconds | About 20 hours | Supported |
| 15m | 900 seconds | About 2.5 days | Supported |
| 1h | 3,600 seconds | About 10 days | Supported |
| 4h | Not provided natively | None | Unsupported; disabled with explanation |
| 1d | 86,400 seconds | About 240 days | Supported |

Each new interval requests up to 240 observations, including the current bucket when returned. Panning and zoom operate within the loaded history; this phase does not add unlimited history backfill.

Coinbase provides a native 6-hour granularity, not 4-hour. v0.6 does not silently substitute it or derive a new interval. Native granularity, maximum 300 candles per request, missing-tick intervals, volume units and polling limitations were verified against [Coinbase's official candle documentation](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles). The implementation reuses the installed [TradingView Lightweight Charts 5.2 API](https://tradingview.github.io/lightweight-charts/docs/api).

## Caching and failure behavior

- Existing server cache, request coalescing, transient retry and provider cooldown are reused.
- 1m history has a 60-second cache lifetime; other new intervals use five minutes. Existing legacy short-range lifetimes remain compatible. Statistics cache for one minute.
- Tab-local validated response caches survive chart remounts and interval changes. Statistics are reused across intervals. Hidden tabs pause chart history/statistics polling; visibility restoration checks the cache before requesting data.
- Retry-After is parsed and bounded for client failures. Failed histories may reuse validated observations explicitly marked stale, with original observation/fetch timestamps. Client history fallback expires after 24 hours; statistics fallback after one hour. Abort does not populate the cache or impose a failure cooldown.
- History validation checks identity, supported granularity, finite OHLCV values, aligned timestamps, strict ordering, requested boundaries and exact missing interval counts. Wrong-asset or malformed responses never replace valid history. An explicit request window handles fetching across a candle boundary.
- A ticker quote and a forming/history candle are separate observations. Chart data is never routed into the paper execution engine.

## Provider limitations and outstanding issues

- 4h is unsupported by the selected provider's native candle endpoint. It requires an explicit aggregation or provider decision in a future phase.
- Historical candles are a REST snapshot, not a streaming feed. Depending on interval, cache lifetimes are one to five minutes. The latest bucket may still change. Coinbase warns that historical data can be incomplete and discourages frequent polling.
- Volume covers the selected Coinbase EUR pair, not global exchange activity. SMA overlays are derived indicators, not independent market observations.
- Preferences persist on the current device/browser, not through hosted account synchronization. Paper state still uses its existing account/local persistence.
- Hosted accounts remain gated off by the existing configuration. Local account/database tests passed; hosted account verification was not performed.
- No known failing validation checks remain. v0.6 requires approval before committing or deploying.
