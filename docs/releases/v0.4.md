## Supabase: verified locally

Browser/server clients are separated. API requests independently verify the user; callers cannot supply another owner. Only public project keys are used; secret/service-role keys are rejected. Cookie-authenticated writes check origin, body size and the full paper schema. The SQL migration uses `auth.uid()`, RLS, restricted table grants, an atomic revision check and per-user operation receipts. Writes are journaled locally before network requests, and retries reuse the same operation ID. One-time imports, account isolation, offline recovery, conflicts and receipt restoration are tested.

The actual SQL migration is executed by the tests in isolated PostgreSQL (PGlite) with test Auth roles and identities. Cloud coordination uses an injected test transport. These checks do **not** establish that a hosted Supabase project is correctly configured.
